# 数据导入格式

导入功能读取的是导出功能生成的格式，不引入额外格式。KML 与 CSV 暂不支持：前者需要另一套 XML 语义，后者无法表达断点与精度信息。

- 入口：我的 → 数据 → 导入数据
- 支持格式：GeoJSON（schema 1 与 2）、GPX 1.1
- 文件上限：50MB、20 万个点。超出上限时应先按时间范围拆分导出

## 1. 坐标系

| 环节 | 坐标系 |
|---|---|
| 文件（GeoJSON、GPX） | WGS-84，国际标准，导出时已由 GCJ-02 转换 |
| 应用数据库 | GCJ-02，与高德底图一致 |
| 导入过程 | 写库前执行 `wgs84ToGcj02()` |

未执行转换时，文件可以正常打开且轨迹形状正确，但在中国境内整体偏移 50 至 550 米。此类错误难以通过肉眼识别，因此代码中不存在跳过转换的分支。

## 2. GeoJSON

### 2.1 结构

```json
{
  "type": "FeatureCollection",
  "schema": 2,
  "generator": "DayTrail 0.4.0",
  "name": "DayTrail",
  "crs": { "type": "name", "properties": { "name": "urn:ogc:def:crs:OGC:1.3:CRS84" } },
  "features": [
    {
      "type": "Feature",
      "properties": {
        "date": "2026-11-18",
        "kind": "track",
        "pointCount": 2,
        "accuracies": [12.0, 30.5],
        "times": ["2026-11-18T08:00:00+08:00", "2026-11-18T08:01:00+08:00"]
      },
      "geometry": {
        "type": "LineString",
        "coordinates": [[121.473701, 31.230416], [121.474701, 31.231416]]
      }
    }
  ]
}
```

坐标顺序为经度在前、纬度在后，符合 GeoJSON 规范。

### 2.2 字段说明

| 字段 | 必需 | 说明 |
|---|---|---|
| `schema` | 否 | 缺失时视为版本 1。大于 2 时直接拒绝并提示升级应用 |
| `generator` | 否 | 生成者标识，仅用于排查问题 |
| `properties.date` | 是 | 归属日期，格式 `YYYY-MM-DD`。不从坐标反推 |
| `properties.kind` | 是 | 仅处理 `track`，`stay` 一律忽略，原因见第 4 节 |
| `properties.times` | 是 | 与 coordinates 一一对应的 ISO-8601 时间，允许带偏移或使用 `Z` |
| `properties.accuracies` | 否 | schema 2 引入。缺失时按 50 米处理 |
| `geometry.coordinates` | 是 | 格式为 `[[lon, lat], ...]` |

坐标与时间数量不一致时，以较短一方的长度为准截断；缺少时间的多余点计入丢弃数量。

## 3. GPX

```xml
<?xml version="1.0" encoding="UTF-8"?>
<gpx version="1.1" creator="DayTrail" xmlns="http://www.topografix.com/GPX/1/1">
  <trk>
    <name>2026-11-18</name>
    <trkseg>
      <trkpt lat="31.230416" lon="121.473701">
        <time>2026-11-18T08:00:00+08:00</time>
      </trkpt>
    </trkseg>
  </trk>
</gpx>
```

- 仅读取 `<trkpt>` 的 `lat`、`lon` 属性及其后的 `<time>` 文本；
- `<wpt>`、`<extensions>` 与命名空间前缀一律忽略；
- 缺少 `<time>` 的点将被丢弃，因为无法确定归属日期与采样间隔；
- 归属日期按本地时区由时间戳推导。GPX 不包含日期属性，这是与 GeoJSON 的语义差异；
- 属性允许使用单引号或双引号，顺序不限。

## 4. 停留与地点的处理

`stay_segment` 与 `place` 属于派生数据，由停留识别与地点归并算法生成。直接导入文件中的停留点会引入与现有地点体系无关联的孤立坐标，进而产生重复地点。因此导入完成后由 `recomputeDay` 重新识别，按既有规则合并或新建。

## 5. 冲突策略

| 策略 | 行为 | 适用场景 |
|---|---|---|
| 跳过（默认） | 该日期已有数据时整体跳过 | 补充其他设备的数据 |
| 合并 | 仅写入时间戳不与库内重复的点 | 多台设备同日分别记录 |
| 覆盖 | 删除该日期已有记录后写入，需二次确认 | 明确以文件内容替换当日记录 |

## 6. 校验规则

| 规则 | 处理方式 |
|---|---|
| 纬度超出 [-90, 90]、经度超出 [-180, 180]，或坐标为 (0,0) | 丢弃并计数 |
| 时间戳不大于 0，或晚于当前时间 1 天以上 | 丢弃并计数 |
| 同一日期内时间差不超过 1 秒且距离小于 5 米 | 保留先出现的一个 |
| 某日有效点少于 2 个 | 整日跳过，无法构成轨迹且无统计意义 |
| 精度缺失或不大于 0 | 按 50 米处理，并限制在 1 至 5000 米区间 |

## 7. 原子性

解析与校验全部在写库之前完成。写入在单个 Room 事务内执行，任一日失败则整体回滚。因此不会出现部分写入的状态：要么全部写入成功，要么数据库内容不变。
